# 記事案テンプレート

記事案をまとめるときの形式。作業フォルダがあるなら `記事案.md` として保存する。6ステップの要点は、書き手に見せて確認をもらうために先に出す。noteに貼るのは「本文(note投稿用)」の範囲だけ。

```markdown
# 記事案: [仮タイトル]

## メタ情報

- 記事の種類: ノウハウ・実務記録
- 想定読者(仕事 / 止まっている作業 / 不安):
- 読後の変化(読者が何を安全に試せるようになるか):
- 検索されたいキーワード:
- 推定文字数:
- ハッシュタグ案(大きな言葉・中くらい・ニッチの3層):
- 外部機能の確認日(変化の速いツールを扱う場合):

## 一次情報

書き手が渡した記録の範囲だけを書く。

- 実際に行った作業と、前後の状態:
- 使ったデータ・設定・スクリプト・画面・ログ:
- 失敗・エラー・迷った判断・やり直した点:
- 変更前に確認したこと、人が承認したこと:
- 実行後に読み戻して検証した結果:
- 外部サービスの公式情報(URLと確認日):

### 到達段階

| 項目 | 実装した | 検証した | 未検証 |
|---|---|---|---|
|  |  |  |  |

## 6ステップ

### 1. 伝えたいこと

→

### 2. ポイント

1.
2.
3.

### 3. 理由・背景(作業・データ・ログ)

| ポイント | 裏づけ(書き手の記録) |
|---|---|
|  |  |

### 4. 伝えたい人

→ 今、                              な人

### 5. 補足・フォロー

- 「自分の仕事には関係ない」と感じそうなこと:
- 説明が要る専門用語・ツール名:
- 自分の環境で試すとき、足りない前提:
- 「戻せなかったら」と不安になりそうなこと:
- 誇張や万能感に見えそうなこと:

### 6. 順番

この順番にする理由:
```
