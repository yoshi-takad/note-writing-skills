# レビューと公開前チェック

本文ができた後に使う。1人(1つのAI)で行うため、視点を切り替えて一つずつ読み直す。同じ流れで書いた直後に評価すると甘くなるので、各視点で本文を頭から読み、該当箇所を短く引用して指摘する。

レビューでは書き直さない。違和感とその理由だけを出し、直すのは書き手の声を保てる形で本文側が行う。

## 目次

- 視点A:読者として読む
- 視点B:事実を確認する
- 視点C:トーンを確認する
- 統合:直す順番を決める
- 簡易チェック(AIらしさ)
- 公開前チェックリスト
- 再レビューの基準

## 視点A:読者として読む

準備で決めた読者の立場になり、「今この瞬間の気持ち」で、本文を上から読む。読者像が属性だけのときは、先に場面と気持ちを具体化する。

次の6点を、該当箇所の引用つきで挙げる。

1. 離脱ポイント:ここで読むのをやめそうな箇所
2. 自分ごとにならない箇所:自分の気持ちと接続しなかった箇所
3. 伝わらない箇所:前提不足、抽象的すぎる言葉、意味が取りづらい箇所
4. 不安が残る箇所:条件、価格、使い方、意味づけで不安な箇所
5. 押しつけに感じる箇所:答えを決められているように感じた箇所
6. 響いた箇所:心が動いた箇所(残すべき部分の確認になる)

出力の形:

```markdown
### 読者として読む
- 読者の状態:
- 離脱ポイント: [引用] → [理由]
- 自分ごとにならない箇所: [引用] → [理由]
- 伝わらない箇所: [引用] → [理由]
- 不安が残る箇所: [引用] → [理由]
- 押しつけに感じる箇所: [引用] → [理由]
- 響いた箇所: [引用] → [理由]
- 読後の状態: 読み終えた後、書き手や対象に近づいたか
```

## 視点B:事実を確認する

本文から、確認が必要な記述を抜き出して判定する。推測で「正確」としない。

確認対象:

- 素材、製法、仕組みなどの説明
- 数字(件数、期間、受賞歴、レビュー数、価格など)
- お客様の声やアンケート由来の主張
- 固有名詞、商品名、シリーズ名の表記
- 書き手の経験として書かれた出来事(これは書き手に確認する。AIが検証できるのは、書き手が話した内容との一致まで)

判定は3種類:

- 正確:資料または書き手の発言で確認できた
- 要修正:不正確、または誤解を招く
- 要確認:現時点では確認できない(書き手に質問する)

本文に、書き手が話していない出来事や感情が入っていないかも、ここで確認する。見つけたら削るか、質問に変える。

## 視点C:トーンを確認する

押しつけ、煽り、万能感、根拠のない成果表現を探す。

- 共感が先にあるか。自己開示があるか
- 断定しすぎていないか
- 説教、煽り、宣伝調になっていないか
- 「〜すべき」「〜しなければいけません」がないか
- 「絶対大丈夫」「頑張れ」のような根拠のない励ましがないか
- 「他にはない」「No.1」「最高品質」のような比較優位表現がないか
- 表記(名称、一人称)が準備で決めたルールと一致しているか
- 締めが行動の強制ではなく、読者の選択や日常に戻す形になっているか

## 統合:直す順番を決める

指摘を重複でまとめ、次の優先順で並べる。

1. 事実の誤り、書き手が話していない内容
2. 読者の不安が残る箇所
3. トーンの逸脱
4. 抽象的すぎて情景が浮かばない箇所
5. 表記ゆれ

指摘同士が矛盾する場合(例:読者には説明が足りないが、トーンは説明過多)は、どちらを優先したか理由を一言添える。反映しない指摘は「保留」として残す。

## 簡易チェック(AIらしさ)

`yomiyasu` が使えない場合の代替。次に当てはまる箇所を探して直す。

- 人でも組織でもないものが主語で、比喩的な動詞を取っている(「〜が壊れる」「〜が効く」「〜が溶ける」など)。誰が何をしたかに戻す
- 「重要なのは〜」「大切なのは〜」のような前置き、「〜ではなく〜」の否定対比の多用
- 絵文字、文末のコロン、意味のない太字、箇条書きの乱用
- 補足のカッコが多い。英単語の前後に不要な半角空白がある
- 「これ」「両者」「片方」など、指す先が遠い指示語
- 同じ意味を言葉を変えて繰り返している段落
- 1文が長く、読点が3つ以上ある

直した後は、書き手の確信度と出来事の大きさが変わっていないか確認する。

## 公開前チェックリスト

### 一次情報と事実

- [ ] 実体験、実際の制作過程、お客様の声などの一次情報が入っている
- [ ] AIが経験・感情・出来事を作っていない
- [ ] 数字の出典または確認元がわかる
- [ ] 画像・スクリーンショットに個人情報や未公開情報がない

### 設計

- [ ] 読者が属性ではなく、場面と気持ちで定義されている
- [ ] ステップ5の補足(伝わりづらい前提、引っかかり)が本文に入っている
- [ ] 冒頭で、何の話かと、なぜ今読むのかが伝わる
- [ ] タイトルは35文字以内で、最初の9文字で入口が見える
- [ ] 一つの段落が一つの前進になっている

### 文章

- [ ] 事実、書き手の判断、推測、一般論が混ざっていない
- [ ] 説教・正解の押しつけ・煽りになっていない
- [ ] 根拠のない励まし、比較優位表現がない
- [ ] 出来事や感情を実際より劇的にしていない
- [ ] 抽象語の前に、具体的な事実がある
- [ ] 長文記事で感嘆符を使っていない(使っても3個以内)
- [ ] 一人称と名称の表記が統一されている
- [ ] AIらしさの除去工程を通し、そのあと確信度と事実の大きさを確認した

### 投稿

- [ ] noteに貼る範囲(タイトルと本文)から、管理用の情報を除いてある
- [ ] 目次はnoteの目次機能を使い、手入力の目次を作っていない
- [ ] 貼り付け後、空ブロックや見出しの崩れがない

## 再レビューの基準

| 変更内容 | やり直す視点 |
|---|---|
| 語尾、表記、軽微な調整 | トーンのみ、または不要 |
| 構成や結論の変更 | 読者として読む、トーン |
| 事実・素材・数字に関わる追記 | 事実の確認 |
| タイトルの変更 | タイトルの基準(9文字、具体性) |
| 大幅な全面修正 | すべて |
